# Bento

**分格装好的 Unity 编辑器工具箱。** 给美术、地编和技术美术用：整理资产、批量改名、搬运文件、处理材质、布置场景，这些零碎又容易出错的活，一个窗口里都能做完。

像便当盒一样，每类工具放在自己的格子里（整理 / 资源、模型和预制体 / 材质 / 场景），常用的可以收藏到“常用”格。

## 为什么放心用

Bento 里所有会改东西的操作，都遵循同一个流程：

1. **先预览**：列出将要修改的每一项，有风险的项会标黄或标红，可以逐项勾选、定位。
2. **再确认**：点击执行前会弹窗确认，危险操作会明确写出后果。
3. **能撤回**：
   - 场景里的修改，整批操作一次 Ctrl+Z 就能撤销。
   - Project 资产的移动和重命名使用 Unity 的安全接口，`.meta` 和 GUID 不变，已有引用不会断。执行后会逐项校验，中途失败自动回滚，并写入“操作历史”，之后也能整批恢复。

少数不可撤销的操作（例如删除文件、跨场景保存）会单独标为高风险，需要手动解锁才能执行。

## 环境要求

- Unity 2022.3 或更新版本
- 只在编辑器中运行，不会进入构建产物
- 材质相关功能以 URP/Lit 为目标 Shader

## 安装

在 Unity 中打开 `Window > Package Manager`，点左上角 `+`，选择 **Add package from git URL**，填入：

```text
https://github.com/nb-diok-in-sky/Bento.git
```

需要固定版本时，在 URL 末尾加上 tag，例如 `...Bento.git#v1.0.0`。

也可以直接编辑项目的 `Packages/manifest.json`：

```json
"com.nbdiok.bento": "https://github.com/nb-diok-in-sky/Bento.git"
```

## 快速上手

1. 菜单 `Tools > Bento > 工具箱` 打开主窗口。
2. 左侧选择分组和功能；窗口较窄时，会变成顶部的两个下拉框。
3. 第一次打开时，“常用”分组里已经预设了最常用的几个功能（批量重命名、Hierarchy 整理、Tag/Layer、预制体替换、资源变体等）。功能名旁边的 ☆ 可以增减收藏。
4. 在 Hierarchy 或 Project 里右键 `Bento > 智能工具`，会根据当前选中的内容，列出能用的功能。
5. 窗口右上角的 📁 可以打开文件夹收藏栏，在做其他操作的同时快速跳转目录。

## 功能一览

下面按工具箱里的分组，逐个说明每个功能。“会改什么”一栏写的是这个功能可能修改的内容，以及修改后能不能撤回。

### 整理

| 功能 | 做什么 | 会改什么 |
|---|---|---|
| **文件夹收藏** | 收藏常用的 Project 文件夹，点一下就在 Project 窗口里定位到它。支持排序、删除、清理已经不存在的收藏。 | 只保存在本机，不影响项目和其他人 |
| **批量重命名** | 自动判断当前选中的是场景对象还是 Project 资产。可以统一改成“前缀 + 基础名 + 后缀 + 编号”，也可以保留原名，只加前后缀。 | 场景对象可以 Ctrl+Z；资产保留 GUID，可在“操作历史”中恢复 |
| **资产移动** | 把选中的 Prefab/模型、材质、贴图、其他资产，按类型分别移动到指定文件夹，移动时可以顺带统一命名。执行前会列出计划和冲突，并可以把移动清单导出到你选择的位置。 | 资产路径改变，GUID 不变；失败自动回滚，可以反向恢复 |
| **操作历史** | 列出所有通过 Bento 做过的资产移动和重命名，可以按 GUID 整批恢复。 | 历史保存在本机 `Library/Bento`，不会进版本控制 |
| **资产信息** | 分析选中的 Prefab、FBX 或文件夹的对象结构，可以导出 JSON，给资产审查或 AI 工具使用。 | 只读 |
| **按后缀清理** | 在指定文件夹里递归查找文件名以某些后缀结尾的文件（例如 `.max`、`.psd`、某级 LOD），勾选后删除。适合清理资源包里带进来的源文件。 | ⚠️ **删除文件，不可撤销**，执行前请确认版本控制可以恢复 |
| **递归抽取资产** | 从多层嵌套的子文件夹里，按类型把资产找出来，平铺移动到同一个文件夹。 | 同“资产移动”，可以恢复上次移动 |
| **Hierarchy 整理** | 把大量场景对象归入一个缓存好的父节点，或者一键为选中对象创建空父物体来分组。会检测“旋转 + 非等比缩放”导致的换父级形变，并提供补偿节点方案。同一页还能批量启用 / 禁用对象，以及禁用 LOD、固定显示 LOD0。 | 保持世界坐标不变，整批一次 Ctrl+Z |
| **场景光源批处理** | 在选中对象及其子物体中查找所有 Light，统一设置为无阴影、硬阴影或软阴影。 | 只改场景实例，不改 Prefab 源；Ctrl+Z |
| **场景物体阴影** | 批量设置 Renderer 的“投射阴影”和“接收阴影”。 | Ctrl+Z |

### 资源、模型和预制体

| 功能 | 做什么 | 会改什么 |
|---|---|---|
| **模型导入** | 选择一个或多个外部模型文件夹，一次跑完整条流程：递归扫描 FBX 和贴图 → 按贴图命名识别 BaseColor / Normal / Mask 等类型 → 创建 URP/Lit 材质并绑定到模型材质槽 → 生成 Prefab。每个 FBX 的计划都可以预览、单独取消。 | 新建材质和 Prefab，修改 FBX 的材质映射 |
| **资源变体** | 把场景里已经调好的对象另存为一个独立的新 Prefab，可以选择同时复制材质和贴图，新 Prefab 会引用这些复制出来的材质和贴图。适合做“换色版”“破损版”这类变体，原资产完全不动。 | 新建资产；支持一键撤销整次生成 |
| **FBX 材质继承** | 两个结构相同的模型，一个材质是对的，另一个是错的。按子物体路径或同名 Renderer 匹配，把参考模型的材质复制到待修复的模型上。 | 修改待修复模型的材质引用 |
| **Prefab Layer** | 按资产类型批量设置 Prefab 的 Layer。不预设任何 Layer 方案，只在你项目已有的 Layer 里挑：资产名包含 Layer 名，或两者属于同一类（例如 `pine_tree` → `Foliage`、`木屋` → `建筑`）；有大中小多个同类 Layer 时按占地尺寸选。匹配不上的保持原样，默认只改仍在 Default 层的节点。 | 修改 Prefab；可恢复上次修改 |
| **Tag/Layer** | 批量设置场景对象的 Tag 或 Layer，可以选择是否包含子物体。 | Ctrl+Z |
| **OBJ 转项目 FBX** | *可选模块。*把 OBJ 的导入结果重新导出为项目内的 FBX。需要安装 Unity FBX Exporter。 | 新建 FBX |

### 材质

| 功能 | 做什么 | 会改什么 |
|---|---|---|
| **Shader 替换** | 把选中的材质球批量切换到另一个 Shader。如果换完以后贴图或颜色丢了，可以用“恢复丢失属性”，从材质的序列化数据里找回来。 | 修改材质 |
| **选中模型材质贴图** | 从场景对象或 Prefab / FBX 出发，找出它实际用到的模型、材质、贴图，可以分别只选中某一类，也可以按三类分别安全移动到指定目录。扫描普通模型时会忽略 Terrain，避免混进地形贴图。 | 只选中不修改；移动时同“资产移动” |
| **选中 Terrain 绘制贴图** | 在 Terrain 的 Paint Texture 中选中某一层后，直接在 Project 里选中这一层对应的**贴图文件**（而不是 Terrain Layer 资产）。 | 只读 |
| **Terrain Layer 生成** | 从选中的贴图或文件夹里，按命名（`_BaseColor`、`_Normal`、`_MaskMap` 等）把贴图分组，批量生成 `.terrainlayer`。缺少基础色的组不会生成，同名文件已存在时跳过，不会覆盖。 | 新建 Terrain Layer，原贴图不动 |

### 场景

| 功能 | 做什么 | 会改什么 |
|---|---|---|
| **场景材质替换** | 在选中对象及其子物体里，把某个旧材质统一换成新材质。常用于刚导入的 FBX 带着一堆默认材质的情况。 | Ctrl+Z |
| **查找材质使用对象** | 拖入一个材质球，列出场景里所有用到它的对象，可以逐个定位，也可以一次全部选中。 | 只读 |
| **场景材质吸管** | 开启后，在 Scene 视图里点击模型表面，就会在 Project 里定位到这块表面用的材质球。多材质模型分不清哪块是哪个材质时很好用。按 Esc 退出。 | 只读 |
| **预制体替换** | 把选中的对象替换成指定的 Prefab 或 FBX，保留父节点和排序，可以选择保留原名和激活状态。也能按名称批量替换整个当前场景。 | 当前场景可以 Ctrl+Z；⚠️“替换所有 Build Settings 场景”会保存多个场景，**不可撤销**，需要手动解锁 |
| **FBX 实例检查** | 找出场景里直接放进来的 FBX / OBJ 实例（而不是通过 Prefab 放的），可以搜索、筛选、定位。 | 只读 |
| **烘焙光照** | 批量开启或关闭所选模型的 Generate Lightmap UVs，按 FBX 资产去重。还可以设置“动态光池”和“静态光池”，烘焙时自动关掉动态光、打开静态光，烘焙结束后恢复原状。也可以从菜单 `Tools > Bento > 烘焙光照` 直接打开。 | 修改模型导入设置（可以恢复上次设置）；灯光只在烘焙期间临时切换 |

### 菜单和右键

| 入口 | 做什么 |
|---|---|
| 右键 `Bento > 智能工具` | 按当前选中的内容（场景对象、光源、Terrain、模型、材质、文件夹……）列出可以用的 Bento 功能 |
| 右键 `Bento > 选中物体使用的全部材质` | 在 Project 中选中所选对象用到的全部材质球 |
| 右键 `Bento > 选中物体的模型、材质和贴图` | 同“选中模型材质贴图”，不打开窗口直接选中 |
| 右键 `Bento > 选中 Terrain 当前 Paint Texture 贴图` | 同“选中 Terrain 绘制贴图” |
| `Tools > Bento > 审计资产引用复用` | 先在 Project 选中文件夹，统计其中每个材质和贴图被多少个模型共用，结果写入 `Temp/Bento_asset_reference_sharing_audit.json`。适合判断能不能安全地修改某张共享贴图 |
| `Tools > Bento > 刷新并输出日志` | 执行一次 AssetDatabase 刷新，并在 Console 里输出耗时 |

更详细的逐步操作说明见 [使用说明](Documentation~/使用说明.md)。

## 可选模块

下面两个模块只在安装了对应的包时才会编译，没装也不影响其他功能。Unity 会自动检测，不需要任何设置。

| 模块 | 需要的包 | 作用 |
|---|---|---|
| OBJ 转项目 FBX | `com.unity.formats.fbx`（Unity FBX Exporter） | 见上方“资源、模型和预制体” |
| AI / MCP | `com.coplaydev.unity-mcp`（MCP for Unity） | 注册一个名为 `bento` 的 MCP 命令，让 AI 客户端可以读取场景和资产状态、生成预览计划、打开对应页面。**AI 不能直接执行修改**，最终写入仍然要在 Unity 里由人确认。页面里还可以一键关闭 MCP 自带的高危通用工具 |

本仓库不保存 `.mcp.json`、密钥或任何个人 AI 配置。

## 扩展：添加自己的页面

在任意引用了 `Bento.Editor` 的编辑器程序集里，给一个类加上特性并实现 `IBentoTool`，它就会出现在工具箱里：

```csharp
using UnityEditor;
using Bento;

[BentoPage("my_tool", BentoGroups.Scene, "我的工具", Order = 100)]
sealed class MyTool : IBentoTool
{
    public void Draw() => EditorGUILayout.LabelField("Hello");
}
```

- 需要响应页面切换或选中变化时，再实现 `IBentoPageLifecycle`。
- 代码里可以用 `BentoWindow.OpenPage<MyTool>()` 打开这个页面。
- `BentoGUI` 提供定位按钮、全选 / 全不选 / 反选、文件夹选择等常用控件；`BentoCommand` 提供“确认 → 执行 → 报错弹窗”的统一流程。

## 目录结构

```text
Editor/
  Framework/              工具箱窗口、页面注册、收藏、右键菜单、公共 GUI
  Common/                 命名、选择、资产信息、安全资产操作与操作历史、材质规则
  Tools/<分组>/<功能>/    每个功能一个文件夹，分组与工具箱界面一致
Optional/
  FbxExporter/            可选模块：OBJ 转 FBX
  Mcp/                    可选模块：MCP 集成
Tests/Editor/             编辑器测试（Unity Test Framework）
Documentation~/           使用说明
```

## 参与贡献

欢迎提交 Issue 和 Pull Request。提交前请确认：

- 在 Unity 2022.3 中编译没有错误。
- 在 `Window > General > Test Runner` 的 EditMode 中运行测试并通过。包内测试默认不显示，需要在项目的 `Packages/manifest.json` 中加入：

  ```json
  "testables": ["com.nbdiok.bento"]
  ```

  测试会在 `Assets/_BentoTestTemp` 下创建临时资产，结束后自动删除。
- 新增会修改资产或场景的功能时，保持“先预览、后确认”的流程，并提供撤销或回滚。
